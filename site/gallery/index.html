Serve — the durable server platform

store · runner · platform

A batteries-included durable server stack composed of store, runner, platform, HTTP/1.1 (std.http), WebSocket (std.ws), and the hirsel host, hirsel deploy, hirsel dev, and hirsel sdk ts CLI commands.

  • Durable storage: copy-on-write B+tree with checksummed journal, concurrent snapshot readers, and single-writer total order (by design, like SQLite WAL), plus Tiered larger-than-RAM storage, S3/Tigris Bucket backing with fencing, and read followers.
  • Rich indexing & projections: secondary, unique, and aggregate indexes; IVF-RaBitQ approximate + exact vector search with prefilters (vector); exact-fraction hybrid RRF (hybrid); BM25 full-text (search); Hilbert-spatial (spatial); row TTL expiry; and incremental projections.
  • Migrations & live sync: transactional Migrate and preview_migration (hirsel dry-run); live diff subscriptions; typed Rooms.
  • TypeScript SDK: hirsel sdk ts generates typed clients with reconnect recovery and optimistic writes.

One Place = one fenced single-writer authority (no in-Place multi-master/Raft clustering by design — scale out across Places, persist durably to S3/Tigris); failed deploys abort automatically before cutover, while post-cutover rollback across a schema migration uses hirsel store restore.

Real-time media & networking in pure Hirsel

62,418 LOC · zero FFI

A complete real-time media and transport stack written in 62,418 lines of pure Hirsel across 11 packages with zero Foreign code, so hirsel test --sim and recorded replay cover it end to end:

  • Transport & security: DTLS 1.2 (dtls), SRTP/SRTCP (srtp), RTP/RTCP with RTX, BWE, and pacing (rtp), jitter buffer (rtp_jitter), STUN/ICE-lite (stun_ice), TURN client & relay (turn), and RFC 9605 SFrame E2EE (sframe).
  • WebRTC SFU & containers: webrtc_sfu (simulcast, VP9/AV1 SVC, dynacast, Opus RED, E2EE clear-range routing), codec bitstream parsers (media_bits), Ogg/MP4/WebM containers (media_container), and room recording (media_record).

Thin C FFI wrappers: opus, av1, h264, image_jpeg, and image_webp are thin C FFI wrappers behind Foreign (trusted native code). They sit outside the 62,418-line pure-Hirsel transport and SFU stack above.

Serving hirsel.ai itself

Dogfooded HTTP/1.1 static asset server

This website is served in production by a native Hirsel executable built on std.http, std.router, std.dir, and std.file. At startup it walks its granted _site directory once without following symlinks, loads assets into memory, and enforces _headers rules under explicit hirsel.toml grants (Net=Listen, _site, Clock, Tasks, Process, Stderr).
